# Regenerating LasB conformers with Zn²⁺/Ca²⁺ explicit: 4/6 now pass validation (was 0/6)

## What changed

The original 6 `lasb_conformer_beta*` receptors were generated by ConforMix/Boltz with no
cofactor specified at all — confirmed in `lasb_zn_transplant_finding.md` to produce a
catalytic site that collapses into the vacated zinc position (His144 at 1.09–1.79 Å from
where Zn²⁺ belongs, a physical clash in all 6 conformers).

Before assuming this required a code fix, the ConforMix/Boltz source was read directly
(`conformix_boltz/src/boltz/data/parse/fasta.py`, `run_conformixrmsd_boltz.py`,
`run_twisted.py`, via a live Colab session). Findings:

- Boltz's native fasta schema supports non-protein entities via `>chain_id|ccd|` records
  (parsed into `{"ligand": {"id": ..., "ccd": ...}}` — standard Boltz input, nothing
  ConforMix-specific needed changing).
- `run_conformixrmsd_boltz.py` passes the fasta path straight through to Boltz's own
  `predict.callback` (`data=str(args.fasta_path)`) with no filtering — any entity in the
  fasta reaches the model.
- The twist-guidance code (`run_twisted.py`) builds its region mask by iterating
  `(atom.chain, atom.resi, atom.name)` per atom via PyMOL — chain/residue-number keyed, not
  index-keyed — so an added ligand chain doesn't corrupt `subset_residues` parsing for the
  protein chain.

Conclusion: no patch needed. Adding `>Z|ccd|\nZN\n` and `>X|ccd|\nCA\n` to the input fasta
was sufficient to make the metals visible to the model.

## Regeneration

Reran the exact same 6-conformer command (`--twist-target-start 0.0 --twist-target-stop 4.0
--num-twist-targets 6 --samples-per-target 1`, same `--subset-residues`, same
`--reference-cif 3DBK.cif`) against `1EZM_with_metals.fasta` (301-aa protein chain + Zn²⁺ +
Ca²⁺ CCD entities). T4 GPU, ~16 minutes total (MSA + 6×diffusion passes).

## Result: self-consistency check, not transplant

Unlike the first attempt, Zn²⁺/Ca²⁺ here are the model's **own predicted positions**, not
copied in from the crystal — this tests whether Boltz can maintain plausible metal-site
geometry when explicitly told the cofactor is present, not whether a fixed external point
happens to land somewhere reasonable.

Applying the identical pre-registered acceptance window used in the original validation
(1.8–3.2 Å for each Zn ligand, 1.8–3.5 Å for each Ca ligand — the same numbers, not loosened
now that results look better):

| Conformer | Zn ligand distances (Å) | Ca ligand distances (Å) | Verdict |
|---|---|---|---|
| β0.0 | 2.28, 1.83, 2.38 | 2.02–3.01 | **ACCEPT** |
| β0.8 | 2.69, 2.08, **1.40** | 2.04–2.80 | REJECT (Glu164–Zn too short) |
| β1.6 | 2.23, **1.79**, 2.25 | 1.92–2.79 | REJECT (0.01 Å under floor — borderline, not a clash) |
| β2.4 | 2.45, 2.36, 1.86 | 2.27–3.06 | **ACCEPT** |
| β3.2 | 1.94, 1.89, 2.08 | 2.38–2.93 | **ACCEPT** |
| β4.0 | 2.13, 2.31, 2.30 | 2.20–3.03 | **ACCEPT** |

**4/6 conformers pass** the same rule that eliminated 6/6 before. The two rejections are
categorically different from the original failure mode: the worst value here is 1.40 Å
(β0.8, Glu164), compared to 1.09 Å with the ring carbon itself overlapping the metal position
in the original run. β1.6 misses the floor by 0.01 Å — noise-level, not a structural collapse.
Full per-conformer, per-atom table:
`results/lasb_ensemble_rmsd/zn_regenerated_validation.csv`.

## What this establishes

The original failure (Step 1 finding) was a usage error, not a fundamental limitation of the
method: Boltz can maintain chemically plausible zinc-site coordination in a majority of
conformers when the cofactor is part of the input specification, at the same guidance
strength and RMSD-target range as before. This directly resolves the ambiguity the pivot was
designed to test — the harder claim ("method cannot maintain metal geometry even when told
the metal is there") is not what happened here.

The 4 accepted conformers (β0.0, β2.4, β3.2, β4.0) proceed to Step 1d (receptor prep) and
Step 3 (docking) as the validated ensemble. β0.8 and β1.6 are excluded and not silently
carried forward, per the pre-registered rule.
